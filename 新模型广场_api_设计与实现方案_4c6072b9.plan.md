# 新模型广场 API 设计与实现方案

## 一、现有系统分析

### 1.1 现有数据结构

| 数据表/实体 | 说明 |
|------------|------|
| `channels` | 渠道表，存储 API 密钥、上游配置、模型列表 |
| `models` | 模型元数据表，存储描述、图标、标签、供应商 ID |
| `abilities` | 能力表，连接渠道和模型（channel_id + model） |
| `vendors` | 供应商表 |

### 1.2 现有 API (`/api/pricing`)
- 返回所有启用的模型列表
- 每个模型独立展示，无版本聚合

### 1.3 现有模型广场的问题
- 模型按单个 model_name 展示（如 `gpt-4o`）
- **缺少版本聚合**：官方模型 key（如 `gpt-4o`）可能有多个版本（`gpt-4o`, `gpt-4o-2024-05-13`, `gpt-4o-2024-08-06`），但现有接口未体现这种层级关系

## 二、版本列表与官方模型的关联关系

### 2.1 核心概念

**只有一个关联方式：通过 `channel.model_mapping`**

```
官方模型 (如 gpt-4o)
├── 上游官方途径 ──────────────────
│   └── 我们定义的 key: "gpt-4o"  (官方版本)
│       上游定义的 key: "gpt-4o"  (实际转发)
│
└── 上游中转站 ────────────────────
    ├── 模式1: 我们定义的 key: "claude-fable-5-a1"  上游定义的 key: "claude-fable-5"
    │           描述: 官方满血版本
    ├── 模式2: 我们定义的 key: "claude-fable-5-b1"  上游定义的 key: "claude-fable-5-xx"
    │           描述: 逆向工具调用
    └── 模式3: 我们定义的 key: "claude-fable-5-c1"  上游定义的 key: "claude-fable-5-www"
                描述: 号池
```

**关键理解**：
- `model_mapping` 的 **key**（我们定义的）= 版本
- `model_mapping` 的 **value**（上游定义的）= 实际转发到上游的模型名
- 上游重新对模型定义了，说明这个跟官方途径有区别，所以就是一个新的**版本**

### 2.2 model_mapping 字段说明

`model_mapping` 是 JSON 对象，格式为 `{"我们定义的key": "上游定义的key"}`：

```json
{
  "gpt-4o": "gpt-4o",
  "claude-fable-5-a1": "claude-fable-5",
  "claude-fable-5-b1": "claude-fable-5-xx",
  "claude-fable-5-c1": "claude-fable-5-www"
}
```

| 字段 | 说明 | 示例 |
|-----|------|------|
| **Key**（我们定义的） | 版本标识，用户请求时使用 | `claude-fable-5-a1` |
| **Value**（上游定义的） | 上游中转站定义的模型名，实际转发时使用 | `claude-fable-5` |

### 2.3 数据层级设计

```
OfficialModel (官方模型)
├── name: "claude-fable-5"              // 官方模型名称
├── display_name: "Claude Fable 5"
```

### 2.4 数据来源汇总

| 数据 | 来源表/字段 | 说明 |
|-----|-------------|------|
| 官方模型信息 | `models` | 描述、图标、标签、供应商 |

| 渠道信息 | `channels` | 渠道名称、类型、状态 |

## 三、API 接口设计

### 3.1 接口路径

```
GET /api/v2/model-square              # 获取模型广场数据（列表）
GET /api/v2/model-square/:model_name  # 获取指定模型详情
```

### 3.2 响应数据结构

**GET /api/v2/model-square**

```typescript
// 响应
{
  success: true,
  data: {
    models: ModelSquareItem[],      // 官方模型列表
    vendors: Vendor[],               // 供应商列表
    tags: string[],                  // 所有标签
    total: number                   // 总数
  }
}

interface ModelSquareItem {
  // 官方模型信息
  id: number                       // models 表的 ID
  name: string                     // 官方模型名称 (如 "gpt-4o", "claude-fable-5")
  display_name: string             // 显示名称
  description: string              // 描述
  icon: string                    // 图标标识
  vendor_id: number                // 供应商 ID
  vendor_name: string              // 供应商名称
  vendor_icon: string             // 供应商图标
  tags: string[]                  // 标签数组

  // 版本信息
  versions: ModelVersion[]        // 该官方模型的版本列表
  version_count: number            // 版本数量

  // 价格信息（取最低价的版本）
  price_info: {
    input_ratio: number
    output_ratio: number
    quota_type: number
  }

  // 能力信息
  capabilities: {
    supported_endpoints: string[]   // 支持的端点类型
    max_context?: number          // 最大上下文
    vision?: boolean               // 是否支持视觉
    streaming?: boolean            // 是否支持流式
  }
}

interface ModelVersion {
  // 核心字段
  model_name: string               // 版本名称（我们定义的 key）
  upstream_key: string             // 上游定义的 key（实际转发用）
  channel_id: number               // 渠道 ID
  channel_name: string             // 渠道名称
  channel_type: number             // 渠道类型

  // 状态和配置
  status: string                  // 状态: enabled/disabled
  priority: int                   // 优先级
  mode_description?: string        // 模式描述（如"官方满血版本"、"逆向工具调用"、"号池"）

  // 价格信息
  price_info: {
    input_ratio: number
    output_ratio: number
    quota_type: number
  }
}
```

```go
package service

import (
    "github.com/QuantumNous/new-api/model"
    "github.com/QuantumNous/new-api/dto"
)

func GetModelSquareData(keyword, vendorID, tag string) (dto.ModelSquareData, error) {
    // 1. 从 model_mapping 提取官方模型名（按上游 key 分组）
    officialModels, err := model.GetOfficialModelsFromMapping(keyword, vendorID, tag)
    if err != nil {
        return dto.ModelSquareData{}, err
    }

    // 2. 获取每个模型的版本列表
    for i := range officialModels {
        versions, err := model.GetVersionsByMapping(officialModels[i].Name)
        if err != nil {
            continue
        }
        officialModels[i].Versions = versions
        officialModels[i].VersionCount = len(versions)
    }

    // 3. 获取供应商列表和标签
    vendors := model.GetVendors()
    tags := model.GetAllTags()

    return dto.ModelSquareData{
        Models: officialModels,
        Vendors: vendors,
        Tags: tags,
        Total: len(officialModels),
    }, nil
}

func GetModelSquareDetail(modelName string) (dto.ModelSquareItem, error) {
    // 获取模型详情
    model, err := model.GetOfficialModelDetail(modelName)
    if err != nil {
        return dto.ModelSquareItem{}, err
    }

    // 获取版本列表
    versions, err := model.GetVersionsByMapping(model.Name)
    if err != nil {
        return dto.ModelSquareItem{}, err
    }
    model.Versions = versions
    model.VersionCount = len(versions)

    return model, nil
}
```

### 4.4 Model 层核心逻辑

**文件**: `model/model_square.go` (新增)

```go
package model

// GetOfficialModelsFromMapping 从 model_mapping 提取官方模型
// 核心逻辑：从 channels.model_mapping 的 value（上流定义的key）提取官方模型名
// 然后按官方模型名分组，收集所有版本（model_mapping 的 key）
func GetOfficialModelsFromMapping(keyword, vendorID, tag string) ([]dto.ModelSquareItem, error) {
    // 1. 获取所有启用的渠道及其 model_mapping
    channels, err := GetEnabledChannelsWithMapping()
    if err != nil {
        return nil, err
    }

    // 2. 从 model_mapping 提取官方模型和版本的映射关系
    // upstreamKey -> []VersionInfo (版本信息列表)
    upstreamToVersions := make(map[string][]VersionInfo)

    for _, ch := range channels {
        if ch.ModelMapping == nil {
            continue
        }

        for ourKey, upstreamKey := range ch.ModelMapping {
            // ourKey: 我们定义的 key（版本）
            // upstreamKey: 上游定义的 key（官方模型）
            version := VersionInfo{
                ModelName:   ourKey,      // 版本名（我们定义的）
                UpstreamKey: upstreamKey,  // 上游 key
                ChannelID:   ch.ID,
                ChannelName: ch.Name,
                ChannelType: ch.Type,
                Status:      ch.Status,
                Priority:    ch.Priority,
            }

            // 按上游 key（官方模型）分组
            upstreamToVersions[upstreamKey] = append(upstreamToVersions[upstreamKey], version)
        }
    }

    // 3. 转换为官方模型列表
    var models []dto.ModelSquareItem
    for upstreamKey, versions := range upstreamToVersions {
        // 获取官方模型的元数据（从 models 表或 abilities 表）
        meta := getModelMeta(upstreamKey)

        // 过滤条件
        if keyword != "" && !contains(keyword, upstreamKey) {
            continue
        }

        models = append(models, dto.ModelSquareItem{
            ID:          meta.ID,
            Name:        upstreamKey,  // 官方模型名
            DisplayName: meta.DisplayName,
            Description: meta.Description,
            Icon:        meta.Icon,
            VendorID:    meta.VendorID,
            VendorName:  meta.VendorName,
            Tags:        meta.Tags,
            Versions:    versions,
            VersionCount: len(versions),
        })
    }

    return models, nil
}

// VersionInfo 版本信息
type VersionInfo struct {
    ModelName       string
    UpstreamKey     string
    ChannelID       int
    ChannelName     string
    ChannelType     int
    Status          string
    Priority        int
    ModeDescription string
}
```
